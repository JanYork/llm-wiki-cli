# lwc v0.19.4

Improve team-memory sync availability and let continuous local editing make progress in both directions.

## Highlights

- Batch snapshot and inventory writes in SQLite transactions instead of committing each object separately.
- Keep expensive space preparation outside the shared control-database write lock. Check current authorization again at the final publication boundary, including recovery operations.
- Coalesce edits into one durable pending batch per space, retain later edits for the next batch, pace successful work and stagger retries. Idle workers avoid repeatedly flushing unchanged reports.
- Apply received changes atomically with object-level checks, preserving independent local edits. Overlapping changes and invalid references retain the existing conflict/rebase workflow for external Agents.
- Check the accepted cloud digest before acknowledging local state, so edits made during upload or remerge remain eligible for the next batch.
- Serve sync progress, receipts and page bodies independently of background search-index recovery. Failed index recovery uses persistent bounded backoff; search explicitly reports when its index is not ready.

## Safety and compatibility

The existing local-first protocol, core-memory coverage, signing identity, permission checks, durable receipts and recovery contracts remain in place. LWC continues to provide CLI/MCP tools and conflict signals to external Agents without calling an LLM.

Full snapshots, checkpoints and an O(n) metadata inventory still have a cost. This release improves batching, availability and convergence; it does not promise a fixed propagation delay or negligible local-write latency on slow storage.

## Verification

Before tagging, Pro passed 28 targeted unit/HTTP regressions and the complete team CLI/MCP/Hook journey. Isolated Linux acceptance covered 14 core object types, authorization revocation, idempotent receipts, interrupted commits and restart recovery. Two continuously editing replicas preserved 4500 existing objects and coalesced 178 new edits into 7 accepted batches; both received remote changes before editing stopped. Local-write p95 was 2.3–2.4 seconds on the tested shared storage.

See [the acceptance report](../team-cloud/sync-availability-acceptance.md) for artifact identities, retained failed observations, workload limits and the final release verification record. These results describe the isolated candidate; the existing business deployment requires a separate upgrade.

## Upgrade

Upgrade the team server and participating clients to 0.19.4 using the existing deployment and installation procedures. Stop the server and back up its data before replacing the binary or image. Preserve the configured data directory, signing material and client replica state; do not recreate spaces or edit databases manually. Resume automatic sync and check progress and page readback after startup.

Install with `npm install -g @i-xor/lwc@0.19.4`, `cargo install lwc --version 0.19.4 --locked`, or the checksum-verified GitHub release assets. Homebrew users can upgrade after the tap formula has been updated. Self-hosted operators can use `ghcr.io/janyork/llm-wiki-cli-team:v0.19.4` once the release workflow publishes it.
